## 5. Issues found

- **All 4 match cases landed in `UNCERTAIN` instead of a clear decision.** Every `bestScore`
  fell in the 0.75–0.79 band, consistently between `ThresholdLow` (0.72) and `ThresholdHigh`
  (0.82), for both same-vehicle and different-vehicle comparisons. This suggests the embedding
  similarity signal has poor separation between "correct match" and "wrong vehicle" — the scores
  for different plates (e.g. 0.7161–0.7899) overlap heavily with scores for the correct plate
  (0.7485–0.7899). Worth investigating whether thresholds need retuning, or whether the
  embedding model/preprocessing needs review, or embedding data quality.
- **match-RGH433.jpeg matched the wrong plate.** The top candidate returned was ANV363
  (score 0.7899) instead of RGH433 (whose own best score was only 0.7496). This is a
  correctness bug/model-quality issue, not just a borderline threshold call — the ranking itself
  picked the wrong vehicle.
- **no-match.jpeg scored 0.7711 against GIY034** (only ~0.05 below `ThresholdHigh`), which is
  close enough to be flagged. If this represents an unrelated vehicle, the embedding space may
  not be discriminative enough at the current threshold settings, risking false positives in
  production.
- Priority for next agent: (1) investigate why `match-RGH433.jpeg` ranks ANV363 above RGH433 —
  check the corresponding upload/test image pairs for correctness, then the embedding/similarity
  pipeline; (2) consider whether `ThresholdHigh`/`ThresholdLow` need retuning given the observed
  score distribution; (3) re-run this suite after any embedding pipeline changes to see if score
  separation improves.
